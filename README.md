# NIVO — متجر أزياء عربي (RTL)

متجر أزياء إلكتروني عربي بتصميم **RTL** بأسلوب «الرفاهية الهادئة» (Quiet Luxury)، وواجهة بالعامية المصرية — مع **استوديو إدارة كامل** محمي بكلمة سر.

> **NIVO** — هدوم تفضل هادية.

## نظرة عامة

المشروع من نوع **Full-Stack Web App**: واجهة React (SPA) + سيرفر API واحد مبني على Hono مع tRPC، وقاعدة بيانات PostgreSQL.

**واجهة المتجر (للزوار):**
- الرئيسية بهيرو كامل الشاشة، شريط متحرك (marquee)، سكشن «بطيء بالقصد»، سكشن إديتوريال، وخدمات.
- المتجر مع فلاتر (كل حاجة / نسائي / رجالي / تريكو) وترتيب وعدّاد وحالة فاضية.
- صفحة منتج، سلة، إتمام طلب (الدفع **كاش عند الاستلام**)، صفحة تأكيد الطلب.
- صفحة تواصل بفورم محدود بـ ٥٠٠ حرف + بانل خريطة مصمّم.
- صفحات معلومات (الشحن، الخامات، الخصوصية، الشروط).

**استوديو الإدارة (`/admin`):**
- دخول بكلمة سر واحدة (افتراضيًا `NIVO555`، قابلة للتغيير عبر متغير بيئة).
- ٤ كروت إحصائيات بعدّادات متحركة، ٣ تبويبات (المنتجات / الطلبات / بيانات الموقع).
- إضافة وتعديل وحذف المنتجات (بما فيها السعر والسعر قبل الخصم)، وإدارة حالات الطلبات، وتعديل اللوجو وبيانات التواصل والسوشيال.

**ملاحظة مهمة:** مفيش بوابة دفع حقيقية — الطلب بيتسجل «كاش عند الاستلام». ومفيش إرسال إيميلات فعلي.

## التشغيل محليًا

### المتطلبات

- **Node.js** ‏≥ 20.19 (مُختبَر على Node 22)
- **pnpm** 11 — لو مش مثبّت: `npm install -g pnpm@11`
- **PostgreSQL** 14+ (محليًا أو أي خدمة مستضافة)

### الخطوات

```bash
# ١) تثبيت الاعتماديات
pnpm install

# ٢) إعداد متغيرات البيئة
cp .env.example .env
#    بعد كده افتح .env وعدّل DATABASE_URL و JWT_SECRET

# ٣) إنشاء الجداول في قاعدة البيانات
pnpm db:migrate

# ٤) تشغيل المشروع (واجهة + API في نفس الوقت)
pnpm dev
```

بعد التشغيل:

| الخدمة | الرابط |
|---|---|
| المتجر | http://localhost:3000 |
| استوديو الإدارة | http://localhost:3000/admin |
| API (Hono) | http://localhost:3001 |

> `pnpm dev` بيشغّل عمليتين مع بعض: `vite` للواجهة على بورت 3000، و `tsx watch` للسيرفر على بورت 3001. الـ Vite بيعمل proxy لطلبات `/trpc` و `/api` و `/app-storage` للسيرفر.

### أوامر متفرقة

```bash
pnpm dev:web      # الواجهة بس
pnpm dev:api      # الـ API بس
pnpm typecheck    # فحص الأنواع
pnpm test         # تشغيل الاختبارات
```

## قاعدة البيانات

المشروع بيستخدم **Drizzle ORM** على PostgreSQL. الجداول كلها تعريفها في `drizzle/schema.ts`:

| الجدول | الوظيفة |
|---|---|
| `products` | القطع: الاسم، الـ slug، المجموعة، الفئة، السعر، السعر قبل الخصم، المقاسات، الألوان، الخامة، الصور، المخزون، مميّز/مخفي |
| `orders` | الطلبات: الكود `NVO-XXXX`، بيانات العميل، العنوان، الإجمالي، الحالة |
| `order_items` | سطور الطلب: اسم القطعة وسعرها وقت الشراء + الكمية والمقاس |
| `messages` | رسائل فورم التواصل |
| `subscribers` | مشتركو النشرة البريدية |
| `site_settings` | إعدادات الموقع: اللوجو، اسم البراند، بيانات التواصل، السوشيال |

### الأوامر

```bash
pnpm db:generate   # توليد migration جديد بعد أي تعديل في schema.ts
pnpm db:migrate    # تطبيق الـ migrations على قاعدة البيانات
```

> **مهم:** ملفات `drizzle/migrations/` هي المصدر الوحيد للحقيقة — متعدّلش قاعدة البيانات يدويًا. أي تعديل في `schema.ts` لازم يتبعه `db:generate` ثم `db:migrate`.

الصور بتتحفظ في `client/public/images/`، والمنتجات في قاعدة البيانات بتشير لمسار الصورة (مثل `/images/hero-coat.jpg`) أو لرابط خارجي.

## متغيرات البيئة

كل المتغيرات في ملف `.env` (شوف `.env.example`). **متضيفش `.env` على GitHub أبدًا.**

### مطلوبة إلزاميًا

| المتغير | الوصف |
|---|---|
| `DATABASE_URL` | رابط اتصال PostgreSQL، مثال: `postgresql://user:pass@localhost:5432/nivo` |
| `JWT_SECRET` | مفتاح توقيع الجلسات — نص عشوائي طويل. توليده: `openssl rand -base64 32` |

### اختيارية

| المتغير | الافتراضي | الوصف |
|---|---|---|
| `ADMIN_PASSWORD` | `NIVO555` | كلمة سر استوديو الإدارة. **غيّرها قبل النشر.** |
| `NODE_ENV` | — | `production` في الإنتاج |
| `PORT` | `3000` | بورت الواجهة (في الإنتاج: بورت السيرفر الوحيد) |
| `API_PORT` | `3001` | بورت الـ API في التطوير |
| `APP_SLUG` | `app` | اسم التطبيق (بيستخدم في اسم كوكي الجلسة) |
| `DB_DRIVER` | `tcp` | `tcp` لـ node-postgres (العادي) أو `http` لـ Neon Serverless |
| `DB_POOL_MAX` | `5` | أقصى عدد اتصالات في الـ pool |
| `AUTH_PROVIDER` | `local` | `local` للمصادقة المحلية |
| `APP_STORAGE_PRESIGN_URL` | فاضي | رابط خدمة التخزين (لو بتستخدم رفع ملفات على منصة) |
| `APP_STORAGE_TOKEN` | فاضي | توكن خدمة التخزين |

> كلمة سر الاستوديو بتتقارن **على السيرفر** بـ `timingSafeEqual`، والكوكي اللي بيتصدر موقّع بـ JWT و `httpOnly` — الباسورد نفسه مش بيتخزن في المتصفح ومش بيرجع في أي رد.

## البناء للإنتاج

```bash
pnpm build
```

البناء بينتج:

- `dist/public/` — ملفات الواجهة الثابتة (Vite build)
- `dist/index.js` — السيرفر محزوم بـ esbuild (ESM)

بعد البناء، شغّل:

```bash
NODE_ENV=production node dist/index.js
```

السيرفر الواحد بيخدم **الواجهة والـ API** مع بعض على `process.env.PORT` — مفيش Vite في الإنتاج.

## النشر

### الخيار ١ — Docker (موصى به)

المشروع فيه `Dockerfile` جاهز (multi-stage: بناء → اعتماديات إنتاج فقط → صورة خفيفة تعمل بـ user غير root).

```bash
# بناء الصورة
docker build -t nivo .

# تشغيلها
docker run -p 3000:3000 \
  -e DATABASE_URL="postgresql://..." \
  -e JWT_SECRET="..." \
  -e ADMIN_PASSWORD="..." \
  -e NODE_ENV=production \
  nivo
```

### الخيار ٢ — أي استضافة Node.js

مناسب لـ Railway / Render / Fly.io / VPS:

1. اربط المستودع.
2. أمر البناء: `pnpm install && pnpm build`
3. أمر التشغيل: `node dist/index.js`
4. اضبط متغيرات البيئة من لوحة الاستضافة (`DATABASE_URL`, `JWT_SECRET`, `ADMIN_PASSWORD`, `NODE_ENV=production`).
5. قبل أول تشغيل، طبّق الـ migrations: `pnpm db:migrate`

### الخيار ٣ — استضافة ثابتة + API منفصل

الواجهة في `dist/public` ممكن تتحط على Netlify أو Vercel أو Cloudflare Pages، والـ API على استضافة Node منفصلة — بشرط ضبط الـ proxy لطلبات `/trpc` و `/api` ناحية سيرفر الـ API.

### قائمة تحقق قبل النشر

- [ ] `JWT_SECRET` مولّد عشوائيًا (مش القيمة الافتراضية)
- [ ] `ADMIN_PASSWORD` متغيّرة عن `NIVO555`
- [ ] `DATABASE_URL` بيشير لقاعدة بيانات الإنتاج + `pnpm db:migrate` اتنفّذ
- [ ] `NODE_ENV=production`
- [ ] ملف `.env` **مش** مرفوع على المستودع
- [ ] HTTPS مفعّل (الكوكيز بتتحط `secure` تلقائيًا في الإنتاج)

## استوديو الإدارة

**الرابط:** `/admin` — **الباسورد الافتراضي:** `NIVO555`

### التبويبات

**١. المنتجات**
- جدول بكل القطع: صورة مصغّرة، الاسم، slug، المجموعة، الفئة، السعر، المخزون، إجراءات.
- فلاتر (الكل / نسائي / رجالي / تريكو) + بحث.
- زر «أضف قطعة» بيفتح فورم فيه: الاسم، الـ slug، المجموعة، الفئة، **السعر**، **السعر قبل الخصم**، المقاسات، الألوان، الخامة، المخزون، الوصف، رابط الصورة، ومفاتيح (مميّز / ظاهر في المتجر).
- في الفورم **معاينة حية للسعر** بتوضّح السعر النهائي وسعر الشطب ونسبة الخصم — والتعديل بيتحدّث فورًا.
- تعديل وحذف أي قطعة، وزر «استعادة البيانات الأصلية».

**٢. الطلبات**
- كل طلب كارت فيه: الكود، شارة الحالة، اسم العميل، التليفون، العنوان، الإجمالي، التاريخ، وقائمة القطع.
- فلاتر بالحالة: الكل / جديد / متجهّز / تم الشحن / تم التوصيل / ملغي.
- منسدلة لتغيير حالة أي طلب.

**٣. بيانات الموقع**
- اللوجو (رفع صورة + رابط + استعادة الأصلي).
- بيانات التواصل (٨ حقول).
- روابط السوشيال (٤ منصات).

> **حساب الأسعار** بيتم **على السيرفر** من أسعار المنتجات المخزّنة في قاعدة البيانات — مش من المتصفح — فإجمالي الطلب مضمون إنه مطابق لأسعار الكتالوج وقت الشراء. وسعر كل قطعة بيتحفظ كـ snapshot في `order_items` عشان الطلب القديم ميتغيّرش لو السعر اتحدّث بعدها.

### تغيير كلمة السر

```bash
# في .env أو من لوحة الاستضافة
ADMIN_PASSWORD="كلمة-سر-قوية-جديدة"
```

## ملاحظات وحدود معروفة

- **مفيش بوابة دفع** — كل الطلبات بتتسجل «كاش عند الاستلام».
- **مفيش إرسال إيميلات** — فورم التواصل بيحفظ الرسالة في قاعدة البيانات، وتأكيد الطلب بيظهر على الشاشة بكود الطلب.
- **الخريطة** في صفحة التواصل بانل مصمّم + لينك خارجي لخرائط جوجل (مش خريطة تفاعلية مدمجة).
- **مفيش تبديل عربي/إنجليزي** — الواجهة عربية RTL بالكامل.
- **الأسعار** بالجنيه المصري (ج.م) وبقت integer لتجنّب أخطاء الفاصلة العشرية.
- **الحركات** كلها بتحترم `prefers-reduced-motion` — لو المستخدم مفعّل تقليل الحركة في نظامه، الأنيميشن بيتوقف.
